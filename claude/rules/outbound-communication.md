# 外部への発信

他人が読む場所への書き込み（メール送信、チャットへの投稿、他人のリポジトリへの PR・Issue・コメント、予定の招待、SNS への投稿、Webhook）は、実行する前に宛先と全文を見せて承認を取る。

## 承認の取り方

- 承認は1回にまとめる。hook（`hooks/check-outbound.sh`）が許可ダイアログを出す操作は、そのダイアログを承認として扱い、チャットで重ねて聞かない。
- hook が見張っていない送信は、チャットで全文を見せ、「送って」と言われてから実行する。
- 文面は改行を実物どおりに見せるため、`text` のコードブロックで示す。
- 下書きのIDだけで送らない。承認する側から中身が見えなくなる。
- 送信コマンドは、ほかのコマンドと `&&` や `;` でつながず、単独で打つ。

## 承認のあと

- 承認を取った文面に文字を足さない。直したくなったら、直した全文を見せて承認を取り直す。
- 断られたら止まる。同じ内容を別のコマンドや別のツールで送り直さない。
- 外部のフォームは、入力を頼まれても送信ボタンは押さない。記入内容を見せて、送ってよいかを聞く。

## 確認しないもの

自分のリポジトリへの commit と push、ローカルの編集、読み取りだけの API 呼び出しは、確認を挟まずに進める。
