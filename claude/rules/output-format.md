# Claude Code の出力フォーマット（チャットパネルの表示）

ユーザーは **Claude Code をほぼデスクトップアプリ（Mac）で使っている**。応答はチャットパネルに表示され、横幅に余裕がない場面が多いため、以下を厳守する。

**HTML 成果物の扱い（どこへ出すか・どう見せるか）は `~/.claude/AGENTS.md`「文章と表示のルール」節が正本。** ここには重複して書かない。

## コードブロックの使い分け

- **長文の日本語テキスト（原稿の採用案・サンプル文章・引用・書き換え案など）をコードブロック（```\`\`\```）で囲まない**
  - コードブロック内は折り返しされず 1 行表示になるため、狭いパネルで見切れて読めなくなる
  - 代わりに **blockquote（`>`）** または **通常の段落** で提示する
- **コードブロックを使うのは以下のケースのみ**:
  - シェルコマンド・実行例（`bash` / `zsh`）
  - ソースコード（`python`, `typescript`, `json`, `yaml` など実コード）
  - 出力結果例（ログ・エラーメッセージ）
  - **メール・Slack・GitHub 等の外部へ送る文面**（下書き・最終版を問わず `text` で囲み、改行と空行を実物どおり見せる。詳細は `rules/outbound-communication.md`）
  - ファイルパス単独提示（インラインの `` ` `` で十分な場合はそちらを優先）

## 採用案・書き換え案の提示フォーマット

原稿の書き換え案やレビュー項目の Before / After を提示する場合は、blockquote を使う：

```
**採用案A**:

> 　CDKを初めて使用するAWSアカウント...以降のCDKデプロイは〜
```

- blockquote 内は通常テキストとして折り返し表示されるため、狭いパネルでも最後まで読める
- 段落のインデント（全角スペース）・Markdown の太字・バッククォートもそのまま blockquote 内で機能する
- **チャットの Before/After は縦の blockquote**。左右2カラムで見比べるのは HTML 側の役目（パネル幅 40〜60 字では左右に割ると読めない）

## 箇条書き・表の取り扱い

- 表（Markdown テーブル）はレンダリングされるため、そのままトップレベルに書いてよい（コードブロックや blockquote に入れない）
- 箇条書き（`-` / `*`）はデフォルトで折り返しされるため問題なし

## URL の前後には半角スペースを入れる

文中に URL を書くときは、**前後に半角スペースを入れる**（特に直前に全角括弧「（」がある場合は必須）。

- 全角括弧の直後に URL を続けて書くと、後ろの全角括弧「）」まで URL の一部と誤認識され、次に半角スペースが出現するまでの範囲が丸ごと Markdown リンクとしてマークアップされてしまう
- 例: `（https://example.com）以降は〜` ではなく `（ https://example.com ）以降は〜` のように URL の前後に半角スペースを挟む

## 横幅の目安

- チャットパネルの幅は **40〜60 文字程度** と想定して書く
- 1 行を長くしすぎない（コードブロック内の横長コマンドは除く）

## 見せる情報はチャットへ積まない

**表を1つでも書くなら、その時点でHTMLにして出す。** チャットパネルの幅では、表も候補の比較も読めない。チャットに残すのは「何を出したか1〜2行と、その置き場」と、決めてほしいこと1点だけ。「質問に答えているだけだから」「決めてほしいことが無いから」と例外を作らない。**例外の判断そのものをしない。**
