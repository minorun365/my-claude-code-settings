# Claude Code の出力フォーマット

応答は幅の狭いチャットパネルに表示される前提で書く。デスクトップアプリでも VS Code 拡張でも横スクロールは読みづらいため、以下を適用する。

## コードブロックの使い分け

- **長文の日本語テキスト（原稿の採用案・サンプル文章・引用・書き換え案など）をコードブロックで囲まない**
  - コードブロック内は折り返しされず 1 行表示になるため、狭いパネルで見切れて読めなくなる
  - 代わりに **blockquote（`>`）** または **通常の段落** で提示する
- **コードブロックを使うのは以下のケースのみ**
  - シェルコマンド・実行例（`bash` / `zsh`）
  - ソースコード（`python`, `typescript`, `json`, `yaml` など実コード）
  - 出力結果例（ログ・エラーメッセージ）
  - ファイルパス単独提示（インラインの `` ` `` で十分な場合はそちらを優先）
- **例外**：メール・Slack・GitHub など**外部へ送る文面**は、改行と空行を実物どおり保持する必要があるため `text` のコードブロックを使う。blockquote では空行が潰れて見え、送信前の確認にならない

## 採用案・書き換え案の提示フォーマット

原稿の書き換え案やレビュー項目の Before / After を提示する場合は blockquote を使う。

```text
採用案A:

> 　CDKを初めて使用するAWSアカウント...以降のCDKデプロイは〜
```

blockquote 内は通常テキストとして折り返し表示されるため、狭いパネルでも最後まで読める。段落のインデント（全角スペース）・Markdown の太字・バッククォートもそのまま機能する。

チャットの Before / After は縦に積んだ blockquote にする。左右2カラムで見比べるのは HTML など幅のある媒体の役目で、40〜60 字幅のパネルで左右に割ると1カラムあたり20字強になり日本語の長文が読めない。

## 箇条書き・表の取り扱い

- 表（Markdown テーブル）はレンダリングされるため、そのままトップレベルに書いてよい（コードブロックや blockquote に入れない）
- 箇条書き（`-` / `*`）はデフォルトで折り返しされるため問題なし

## URL の前後には半角スペースを入れる

文中に URL を書くときは**前後に半角スペースを入れる**。とくに直前が全角括弧「（」の場合は必須。

全角括弧の直後に URL を続けて書くと、閉じ括弧「）」まで URL の一部と誤認識され、次に半角スペースが出現するまでの範囲が丸ごとリンクとしてマークアップされる。

- NG: `（https://example.com）以降は〜`
- OK: `（ https://example.com ）以降は〜`

## 横幅の目安

- チャットパネルの幅は **40〜60 文字程度** と想定して書く
- 1 行を長くしすぎない（コードブロック内の横長コマンドは除く）
