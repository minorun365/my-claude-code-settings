# 学習ループ（保存先の粒度）

全体像——トリガーの見極め、スコープ判断、ウェイクワード「学習しといて」の運用、伝播まで1セット——の正本は `AGENTS.md`「学習ループ」節（クロスツール共通）。このファイルには保存先の粒度とアンチパターンだけを置く。

## 保存先の判断

1. **スコープ**：他プロジェクトでも使う汎用知識か、今のプロジェクト固有か
2. **種別**：ルール / ナレッジ / 技術設定 / ワークフロー / 本人固有情報か
3. **既存統合**：該当する既存セクション・skill があれば追記。なければ新規。重複は `grep -rn` で全ファイル横断確認

| スコープ → | ユーザー（全プロジェクト共通） | プロジェクト（リポジトリ固有） |
|---|---|---|
| ルール・ガイドライン | `~/.claude/rules/*.md` | `<repo>/CLAUDE.md` or `<repo>/.claude/rules/*.md` |
| ナレッジ・学び | `~/.claude/skills/kb-*/SKILL.md`（既存 or 新規） | リポジトリ既存の記録先（README / ADR / Issue など） |
| 技術設定（permissions 等） | `~/.claude/settings.json` | `.claude/settings.local.json` |
| ワークフロー・手順 | `~/.claude/skills/*/SKILL.md` | リポジトリ既存の手順書や README |
| 本人固有情報・継続的な好み | ダイナミックメモリ | プロジェクトメモリ |

## ツールをまたぐときの制約

ダイナミックメモリ（`~/.claude/projects/.../memory/`）は Claude Code 専用で、他のエージェントツールからは読めない。**両ツールで効かせたい学びは `AGENTS.md` または共有スキル側へ書く。**

同じ理由で、`.claude/skills/` と他ツールのスキルディレクトリは同内容へ揃えるのを原則とする。**ただし、片方のツールに実行させたくない手順があるなら、意図的に非対称にしてよい**（読めなければ実行しようがない、という形で担保する）。この場合は差分を見つけても「同期漏れ」として戻さないよう、その旨を明記しておく。

## 蓄積そのものが劣化になりうる

**学びがない日は無理に絞り出さない。** ノイズルールの蓄積は設定の劣化そのもので、そのままコンテキスト消費になる。無条件ロードされる行数（`AGENTS.md` ＋ `CLAUDE.md` ＋ 常時読み込みの rules）は定期的に実測し、増える一方になっていないか確認する。

- 公式の目安は1ファイル200行未満（ https://code.claude.com/docs/en/memory ）
- 増やす提案だけでなく、**重複の統合・矛盾の解消・陳腐化した記述の削除**を同じ頻度で行う
- 削除済みのツール・ファイル・MCP への参照、期限切れの時限記述、解決済みの暫定運用が残りやすい

## アンチパターン

- ❌ 失敗直後に反映せず記憶が薄れる／「次回気をつける」で終わる
- ❌ プロジェクト固有をユーザースコープに書く（または逆）
- ❌ 反映後の同期 / push を忘れて他の端末に伝播しない
- ❌ 同じナレッジを複数ファイルに重複させる
- ❌ ユーザーに「覚えておいて」と言わせるまで動かない（**先回りすべき**）
- ❌ 禁止事項をルールへ書いたのに、そのルール文自身が禁止した表現の用例を持っている（毎セッション読み込んで再吸収する経路になる）。指摘を受けたら自分の出力を直すだけで終わらせず、設定ファイル全体を検索して同じ表現を掃除する
