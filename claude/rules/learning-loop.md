# 学習ループ（Claude Code 固有の補足）

学習ループの全体像——トリガーの見極め、スコープ判断、ウェイクワード「学習しといて」の運用、保存先ルーティング（覚えたい内容→保存先→伝播手段）、伝播まで1セット——の正本は `~/.claude/AGENTS.md`「学習ループ」節（クロスツール共通）。このファイルには Claude Code 固有の保存先の粒度・過去の反映実績・アンチパターンだけを置く。

## 恒久化してよいのは、確かめた事実だけ

**原因の仮説・対処法・制約は、自分で1回確かめるまで設定ファイルへ書かない。** 設定ファイルへ書いた誤りはチャットの誤りと違い、全セッション・全リポジトリへ配られ、次のセッションがそれを前提に動く。指摘を受けた直後ほど「対策を入れました」と報告したい圧がかかり、検証を飛ばしやすい——**謝罪の代わりに設定ファイルを書き換えない**。確かめる前に書きたくなったら「こう見えますが、確かめますか」と1行で聞く。誤って書いたら削除して `rg` で残存0件を確認する。

## 同じ指摘が再発したら、ルールを足す前に「なぜ発火しなかったか」を直す

**再発した指摘の大半は、ルールが無いのではなく、あるのに読まれていない。** そこへ新しいルールを足すと、
読まれない文章がもう1本増えるだけで、次も同じ指摘を受ける。まず次の順に原因を切り分ける。

1. **そもそも開いたか。** スキルは呼ばないと読めない。常時ロードのルールに「着手前に◯◯を開く」が
   書かれているか、書かれていても**参照先として文中に埋まっていないか**を見る
2. **発火の位置が遅くないか。** 「書き終えたらセルフレビュー」と書いてあると、書く前には効かない。
   守らせたい規則は**着手の手順**として書く
3. **機械で止められないか。** 注意書きは読まなければ発火しない。検査スクリプトにすると、
   忘れても止まる（例: 禁止語彙を数える検査スクリプト）
4. ここまでやってから、**本当に新しい規則だけ**を足す

## 保存先の判断（Claude Code の具体パス）

1. **スコープ**：他プロジェクトでも使う汎用知識か、今のプロジェクト固有か
2. **種別**：ルール / ナレッジ / 技術設定 / ワークフロー / 本人固有情報か
3. **既存統合**：該当する既存セクション・skill があれば追記。なければ新規。重複は **`rg -n`** で全ファイル横断確認（設定ディレクトリがシンボリックリンクだと `grep -rn` は空振りしうる。`rules/development.md` の該当節を参照）
4. **常時ロードへ足したら量を見る**：`~/.claude/AGENTS.md` や `paths:` 無しの `rules/*.md` へ追記したら、常時ロード合計（AGENTS.md ＋ CLAUDE.md ＋ `paths:` 無しの rules）を `wc -l` で実測し、目安の上限（1,350行程度）を超えていたら同じターンで作業種別の限られる内容を `kb-*` スキルへ移す（`rules/` は Codex へミラーされないので、そこへ移すのは減量にならない）

| スコープ → | ユーザー（全プロジェクト共通） | プロジェクト（リポジトリ固有） |
|---|---|---|
| ルール・ガイドライン | `~/.claude/rules/*.md` | `<repo>/CLAUDE.md` or `<repo>/.claude/rules/*.md` |
| ナレッジ・学び | `~/.claude/skills/kb-*/SKILL.md`（既存 or 新規） | リポジトリ既存の記録先（README / ADR / Issue など） |
| 技術設定（permissions 等） | `~/.claude/settings.json` | `.claude/settings.local.json` |
| ワークフロー・手順 | `~/.claude/skills/*/SKILL.md` | リポジトリ既存の手順書や README |
| 本人固有情報・継続的な好み | メモリ `feedback_*.md` / `user_*.md` | プロジェクト memory |

> ダイナミックメモリ（`~/.claude/projects/.../memory/`）は Claude Code 専用で Codex から読めない。両ツールで効かせたい学びは AGENTS.md / 共有スキル側へ書く（AGENTS.md「ウェイクワード」節の保存先ルーティング参照）。

## 主な反映実績（抜粋）

過去の失敗 → 反映の代表例。完全な履歴は各設定ファイルの `git log` で追える：

- ファイル名の U+2019／ZIP 日本語化け（`ditto` 使用）／PDF はテキストレイヤー優先 → [`working-with-files.md`](working-with-files.md)
- Bash 並列の CWD 干渉（`git -C` 推奨）／`git add` の並行セッション巻き込み／jq の `\(...)` 補間衝突 → [`development.md`](development.md)
- Chrome DevTools MCP の大量フォーム context 節約／gh CLI マルチアカウント
- 公式 MCP の `get_*_guide` を一次情報として最優先・二次情報の矛盾を黙殺しない → [`tech-writing-verification.md`](tech-writing-verification.md)
- 他者の共有スペースへの発信は事前確認 → [`outbound-communication.md`](outbound-communication.md)

## アンチパターン

- ❌ 失敗直後に反映せず記憶が薄れる／「次回気をつける」で終わる
- ❌ プロジェクト固有をユーザースコープに書く（または逆）
- ❌ 反映後の sync / push を忘れて他 Mac に伝播しない
- ❌ 同じナレッジを複数ファイルに重複
- ❌ ユーザーに「覚えておいて」と言わせるまで動かない（**先回りすべき**）
- ❌ ルールを「抽出・移設する対象」として読んだだけで、同じターンで作っている自分の成果物へ適用しない（見本・サンプルは、その規則が守られている実例でなければ見本にならない）
