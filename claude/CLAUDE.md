# Claude Code 固有の補足

AGENTS.md の共通ルールに加え、Claude Code だけに関わる運用を置く。詳細ルールは `rules/*.md` に分けてある。

## モデルと effort

`settings.json` の `effortLevel` は `medium` を出発点にする（Opus 5.5 の公式の出発点で、Opus 5 の `high` と同等以上）。Fable 5.1 の出発点は `high` なので、Fable を使うセッションだけ上げる。思考の量は effort で決まるので、「よく考えて」「考えずに」のような文は設定ファイルにもプロンプトにも書かない。スキルの frontmatter に `model` を書かない理由は、`rules/` のスキル作成ルールに置いてある。

## MCP の接続状況は「ツールが呼べるか」で判断する

`claude mcp list` の `✔ Connected` は「サーバーと通信できた」であって「ツールが使える」ではない。Connected と出ているコネクタからツールが1つも露出していないことがある。コネクタ由来の接続も `claude.ai <サービス名>` として同じ一覧に出るが、これは `~/.claude.json` の `mcpServers` ではない。

公式プラグイン由来の MCP は、ターミナルの `claude` から `/mcp` で認証する。デスクトップアプリの `/mcp` はコネクタの設定画面へ飛ぶため、プラグイン由来の MCP を認証できないことがある。

## 定期実行ルーチンの設計則

夜間の振り返りや定期チェックのようなルーチンは、クラウド側の定期タスク機能ではなく、**ローカルのスケジューラ（macOS なら launchd）＋ルーチン専用の設定ディレクトリ（`CLAUDE_CONFIG_DIR`）** で動かす。クラウド側の登録はアカウントに紐づくため、対話セッションで使うアカウントを切り替えた瞬間に見失う。

**結果の出口は、ユーザーが日常的に見る固定の1か所へ寄せる。これを設計から外さない。** ターミナルのログ・状態ファイル・Issue を出口にすると、どれも日常的には見ないので「動いているのに誰にも届かない」状態になる。

- 出口のページは固定1枚を上書きし、履歴はページ内に直近数件を折りたたみで持たせる
- ルーチン本体は結果を `runs/YYYY-MM-DD.md` のような日付つき Markdown へ書くところまでにし、見せる形（HTML）への整形は別の処理に分ける。責務を分けると、整形側だけ単体で走らせて検証できる
- **「移行」「移設」も設計変更として扱い、着手前に相談する。** 技術的な移設のつもりでも、出口や見え方が変わるなら運用設計の変更であり、失われるのはたいてい可視性。「これは誰がどこで結果を見るのか」を1行で答えられないなら、まだ設計が終わっていない

## 設定はリンク方式で同期する

`~/.claude/` の rules・skills・agents・hooks・CLAUDE.md・AGENTS.md・statusline は、dotfiles リポジトリの実体へのシンボリックリンクにしておく。編集した瞬間にリポジトリの中身が変わるので、コピー同期の工程が要らない。コミットとプッシュは定期ジョブに任せ、急いで他の端末へ伝えたいときだけ手動で行う。リンクにできないファイル（`~/.claude.json` の `mcpServers` のように機密のマスクが要るもの）だけを、同期用のスキルやスクリプトで扱う。

リンクにすると検索コマンドの挙動が変わる点に注意する（`rules/development.md` の該当節）。
